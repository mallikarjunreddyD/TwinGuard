# Fusion architecture

Phase 4 is a deterministic advisory module in the existing modular monolith. fusion/models.py defines versioned Pydantic evidence, policy, time/compatibility decisions, advisory records and checkpoint state. adapters.py consumes public GeometryResult/RegistrationResult, ThermalResult, OperatingPrediction and SensorObservation records. temporal.py, spatial.py and dependence.py qualify evidence; engine.py evaluates F1 and the fixed experimental F0 comparator; lifecycle.py owns persistence, acknowledgments, recovery and idempotent record transitions. io.py/cli.py provide verified offline ingestion, serialization and replay. Restricted evaluation/fusion_* modules generate and score E3; they are never imported by the fusion core.

The pure interface is assess(state, newly_available_evidence, policy, assessment_time, actions, method, mode), returning a new state and per-asset DecisionTrace objects. Input state is copied, supplied UTC times drive every decision, and no wall-clock read or network/plant operation occurs inside assessment. Batch replay groups delivery by availability; checkpoints bind policy hash and F0/F1 method. Changing policy or moving backwards requires a new explicit replay.

New contracts are additive; existing ConditionAssessment and Phase 3 analytics contracts keep their meanings. A DecisionTrace embeds the original assessment plus policy hash, current positive and qualified negative references, historical positive references, missing requirements, rejected alternatives, compatibility findings, conflicts, actions and lifecycle IDs. Confidence is categorical, not a fabricated probability.

Each run stores evidence/input snapshot manifest, policy and hash, assessment/history, advisory/event records, state checkpoint, processing metrics, provenance and a SHA256 seal. Source observations and normalized records are retained rather than silently overwritten. FusionEvidenceManifest is validated and checksum-verified before ingestion. Import-boundary auditing prohibits fusion imports of plant, sensing implementations, private scenario configuration or evaluation.

This is a research batch/replay implementation, not a production stream store. Long-lived Phase 5 services will need bounded archival/retention, authenticated ingestion/operator actions, durable storage, approved calibration/limits and operational monitoring. The function signature and public records permit those adapters without introducing brokers or plant control into the core.
